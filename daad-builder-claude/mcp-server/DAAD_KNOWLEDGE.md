# DAAD Builder MCP Server - Knowledge Base for Claude

## What is DAAD?

DAAD (Diseñador de Aventuras AD) is a text adventure game engine from the 1980s-90s that runs on retro computers: ZX Spectrum, Commodore 64, Amstrad CPC, MSX, Amiga, Atari ST, and MS-DOS. DAAD Builder is a modern visual tool for creating DAAD games.

## Architecture

The pipeline is: **JSON game data** → **codegen.rs** generates `.dsf` source → **drf.exe** compiles to intermediate JSON → **drb.php** produces `.ddb` binary.

The MCP server talks to the DAAD Builder Tauri app via REST API on port 3042.

## Process Tables (PRO 0-255)

DAAD games use process tables for game logic. 256 tables are available (PRO 0-255).

### Standard tables (auto-generated by codegen):
- **PRO 0**: Location loop — runs every turn. Handles dark flag, pictures, description. Put per-turn events here with verb=_ noun=_.
- **PRO 1**: Input loop — PARSE, turn counter, calls PRO 5.
- **PRO 2**: Parse error handler.
- **PRO 3**: Post-description — LISTOBJ shows objects in room.
- **PRO 4**: Auto-events — runs before each input prompt. Use for timers, NPC schedules.
- **PRO 5**: Response table — matches player verb/noun input. **This is where most game rules go.**
- **PRO 6-12**: Infrastructure (init, windows, status bar, exits, turns).

### Custom tables:
- **PRO 13-255**: Free for game use. Called via `PROCESS N` action from other rules.

### Rule assignment:
- Put player commands (EXAMINE, TAKE, USE, ASK, DRIVE, etc.) in **PRO5**
- Put per-turn events (NPC follow, state checks) in **PRO0** with verb=_ noun=_
- Put timers and schedules in **PRO4** with verb=_ noun=_

## Vocabulary System

DAAD uses a 2-word parser: VERB + NOUN.

- Words are truncated to 5 characters internally
- Nouns with ID < 20 are "conversion nouns" (auto-convert to verbs for directions)
- Directions N/S/E/W/NE/NW/SE/SW/U/D are nouns with IDs 2-13
- IN/OUT are verbs with IDs 12-13
- Standard system verbs: GET(20), DROP(21), REMOVE(22), WEAR(23), R(24), QUIT(25), SAVE(26), LOAD(27), L/LOOK(30), ASK(31)
- Game verbs start at ID 40+
- Game nouns start at ID 50+

## Flag System

DAAD has 256 flags (0-255), each holding a value 0-255.

### System flags (0-63, managed by interpreter):
- **Flag 0**: Dark (set to make current room dark)
- **Flag 1**: Number of objects carried (auto-updated)
- **Flag 28**: DarkF (dark flag after light source check)
- **Flag 30**: Score
- **Flag 31**: Turns (low byte)
- **Flag 33**: Current verb
- **Flag 34**: Current noun
- **Flag 37**: Max carry objects
- **Flag 38**: Player location (read-only, set by GOTO)
- **Flag 42**: Prompt (0=use ">", 1-4=cycle "What now?" messages)
- **Flag 52**: Strength (max carry weight)

### User flags:
- **Flags 64-255**: Free for game use. Use for puzzle states, conversation tracking, evidence flags, timers.

## Condact Reference (Conditions + Actions)

### Common Conditions:
- `AT {locno}` — player is at location
- `NOTAT {locno}` — player is NOT at location
- `PRESENT {objno}` — object is here (at location, carried, or worn)
- `ABSENT {objno}` — object is NOT here
- `CARRIED {objno}` — player is carrying object
- `NOTCARR {objno}` — player is NOT carrying
- `WORN {objno}` — player is wearing object
- `ZERO {flagno}` — flag value is 0
- `NOTZERO {flagno}` — flag value is not 0
- `EQ {flagno} {value}` — flag equals value
- `GT {flagno} {value}` — flag greater than value
- `LT {flagno} {value}` — flag less than value
- `CHANCE {percent}` — random chance (0-100)

### Common Actions:
- `MESSAGE {mesno}` — display message (or use `text` field for inline text)
- `GOTO {locno}` — move player to location
- `SET {flagno}` — set flag to 255
- `CLEAR {flagno}` — set flag to 0
- `LET {flagno} {value}` — set flag to specific value
- `PLUS {flagno} {value}` — add to flag (capped at 255)
- `MINUS {flagno} {value}` — subtract from flag (floored at 0)
- `GET {objno}` — pick up object
- `DROP {objno}` — drop object
- `CREATE {objno}` — make object appear at current location
- `DESTROY {objno}` — remove object from game (to limbo)
- `PLACE {objno} {locno}` — place object at specific location
- `DONE` — stop processing, command was handled
- `NOTDONE` — continue processing (command not fully handled)
- `END` — game over
- `RESTART` — restart from PRO 0 (redescribe location)
- `PROCESS {prono}` — call another process table
- `SYSMESS {sysno}` — display system message
- `DESC` — describe current location (or `DESC @Player` for indirection)
- `AUTOG` — auto-get with weight/carry limit checking
- `AUTOD` — auto-drop

### Important Patterns:

**Examine an object:**
```
verb=L, noun=RULER, process=PRO5
conditions: PRESENT {objno: 0}
actions: MESSAGE {text: "A wooden ruler with markings."}, DONE
```

**Locked door:**
```
verb=OPEN, noun=DOOR, process=PRO5
conditions: AT {locno: 5}, CARRIED {objno: 3}, ZERO {flagno: 64}
actions: MESSAGE {text: "You unlock the door."}, SET {flagno: 64}, DONE
```

**NPC follow (per location):**
```
verb=_, noun=_, process=PRO0
conditions: AT {locno: 1}
actions: PLACE {objno: 5, locno: 1}
```

**Timer countdown (PRO4):**
```
verb=_, noun=_, process=PRO4
conditions: NOTZERO {flagno: 64}, GT {flagno: 65, value: 0}
actions: MINUS {flagno: 65, value: 1}
```

**Random atmosphere:**
```
verb=_, noun=_, process=PRO4
conditions: CHANCE {percentage: 15}, AT {locno: 3}
actions: MESSAGE {text: "You hear a distant sound..."}, DONE
```

## Object Properties

- **noun**: 5-char vocabulary word (e.g. "KEY", "RULER")
- **adjective**: optional disambiguator (e.g. "RED", "OLD")
- **weight**: 0-63 (0 = weightless, 20+ = immovable/scenery)
- **isContainer**: can hold other objects
- **isWearable**: can be worn
- **isTakeable**: can be picked up
- **isLightSource**: provides light in dark rooms (Object 0 is always checked)
- **isPSI**: is a character (Player Similar Individual)
- **otxText**: display name for LISTOBJ (e.g. "the wooden ruler", "Louis Carlyle")
- **attributes**: bit indices 0-15 for HASAT/HASNAT testing
- **location**: "at" (locationId), "carried", "worn", "limbo", "inside" (containerId)

## Status Bar Configuration

The status bar (top line) can be configured:
- **paper_color**: background (0-15, default 4=red)
- **ink_color**: text (0-15, default 15=white)
- **show_location_name**: show room name on left
- **right_content**: "turns", "score", "custom", or "none"
- **right_flag_id**: which flag to display (30=score, 31=turns)
- **right_label**: text before the number (e.g. "Score: ", "Time: ")

## System Messages (STX 0-64)

Customizable text shown by the interpreter:
- 0: "It's too dark to see anything."
- 6: "I don't understand that."
- 7: "I can't go that way."
- 8: "I can't do that."
- 33: ">" (prompt character)
- 36: "I now have _." (_ = object name)
- 63: "You see nothing special about the _."

Override via update_game_settings with system_messages parameter.

## Tips for Claude

1. Always set verb and noun explicitly on rules. Use "_" for wildcards.
2. End response rules (PRO5) with DONE to prevent fall-through.
3. Use inline `text` field on MESSAGE actions instead of message indices.
4. Use flags 64+ for game variables (0-63 are system flags).
5. Object 0 is always the light source for dark rooms.
6. Use PLACE to move NPCs between locations in PRO0 rules.
7. Use CHANCE condition for random events in PRO4.
8. Container objects should not have the same ID as a location.
